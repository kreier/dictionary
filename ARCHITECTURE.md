# Architecture

## Overview

The dictionary project provides a static web interface for browsing
dictionary data.

The authoritative dictionary data is maintained in the separate repository:

https://github.com/kreier/timeline

The current data flow is:

    kreier/timeline/db/*.csv
             |
             v
    scripts/generate-data.py
             |
             v
    public/data/*.json
             |
             v
       Vite frontend
             |
             v
          dist/
             |
             v
       GitHub Pages

## Source of truth

The source of truth for dictionary data is:

    kreier/timeline/db/

The CSV files in:

    archive/data/

are historical copies and are not authoritative.

## Generated JSON

The generated JSON files are stored in:

    public/data/

These files are committed to the dictionary repository because they are
the read-optimized data consumed directly by the static website.

The file:

    public/data/.source.json

records the Timeline Git commit from which the JSON data was generated.

## Data generation

Dictionary JSON is generated by:

    scripts/generate-data.py

For example:

    python scripts/generate-data.py --source archive/data

The GitHub Action normally generates the production data from:

    kreier/timeline/db/

## Frontend

The frontend is a Vite application.

The application entry point is:

    index.html

The application itself is implemented in:

    src/main.ts

Styling is contained in:

    src/style.css

The frontend is currently implemented using vanilla TypeScript and does not
use React, Vue, or another frontend framework.

## Current frontend functionality

The dictionary viewer currently supports:

- language selection;
- loading the corresponding JSON dictionary;
- category selection;
- TEXT;
- BIBLE;
- A6;
- B9;
- WIKI;
- OTHER;
- checked/total counters for each category;
- search by key;
- search by English text;
- key selection;
- previous/next navigation;
- display of dictionary fields;
- checked status;
- checked-by information;
- checked date;
- edit mode activation with editor attribution;
- in-place editing for Text and Notes;
- before/after diff preview modal for proposed changes;
- placeholder for timeline preview.

The Cloudflare security check and automated pull request submission will be integrated in subsequent steps.

## GitHub Pages

The intended production build is:

    npm run build

which creates:

    dist/

The `dist/` directory is a build artifact and is not committed.

GitHub Pages will eventually publish the Vite build rather than the old
Python-generated `docs/index.html`.

## Future editing architecture

The editing and submission flow is:

    Browser (Dictionary Web App)
       │  User modifies Text/Notes/Checked in Edit Mode
       │  Clicks "Submit Changes"
       ▼
    Cloudflare Worker (`dictionary-submissions`)
       │  • Validates Turnstile bot check
       │  • Authenticates via private GitHub Token
       │  • Creates GitHub Issue with diff table + JSON block
       ▼
    GitHub Issue created in `kreier/timeline`
       │  • Title: [Update Translation] VI: key1, key2 (by EditorName)
       │  • Labels: update-dictionary, lang:vi
       ▼
    Review & Approval (Maintainer)
       │  Maintainer comments `/approve` or `/approved` on the Issue
       ▼
    GitHub Action (`approve-translation.yml`) in `kreier/timeline`
       │  • Parses JSON payload from issue
       │  • Updates `db/dictionary_<lang>.csv`
       │  • Commits changes to `main`
       │  • Closes the issue
       ▼
    Dictionary Synchronization Workflow
       │  • Triggered automatically / on schedule
       │  • `scripts/generate-data.py` regenerates `public/data/*.json`
       ▼
    Live dictionary updated on GitHub Pages

The browser must never contain credentials capable of directly modifying
the Timeline repository.
